## RTM Governance

Every `FR-IR-xxx` in the authoritative FRS must appear exactly once as an explicit requirement row in this matrix.

A `COVERED` disposition means the baseline identifies an applicable technical/test/milestone path. It does not mean the feature has already been implemented.

During implementation, test-domain placeholders such as `TEST-PUR` or `TEST-ACC` shall be refined to concrete automated test identifiers where useful without losing the FR/TR relationship.

If an implementation milestone discovers that an RTM mapping is wrong or incomplete, the agent shall report the discrepancy rather than silently changing requirement semantics.

## Implementation Gate

Before a milestone is marked DONE:

1. applicable FRs must remain mapped;
2. applicable TR/ADR constraints must be satisfied;
3. required automated tests must exist and pass;
4. any architecture deviation must have an approved ADR;
5. RTM coverage must be updated if implementation introduces an approved traceability refinement.
